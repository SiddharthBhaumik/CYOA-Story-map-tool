    Method

    This is the exact procedure the page runs. It checks every combination, so nothing is missed and nothing is estimated.

    1. List the switches
    Every starting event and every isolated event is a switch that is on or off. With n switches there are 2 to the power n combinations. Each combination is one complete set of choices.
    2. Play one combination
    Go through the sections in order. In a node, a formula is true when every event it needs is on. The output of a true formula switches on in the next section.
    3. Overlapping formulas
    If a formula needs all the events of another formula and more (A + B + C against A + B), the bigger one wins and the smaller one is blocked. If two true formulas cannot be ranked this way, the node has a conflict, stays silent, and is reported.
    4. Read the ending
    The events that are on in the last section are the endings reached. If none is on, the combination is a dead end.
    5. Find the route
    Start at the ending and walk backwards through the formulas that gave each event. The set of formulas on that backward chain is the route. Combinations with the same ending and the same route are grouped together.
    6. Compress the combinations
    Combinations that differ by one switch are merged, again and again, until the remaining patterns cannot merge. Each pattern says which events must happen, which must not, and which can go either way.
    7. Checks
    The same run reports conflicts, endings that no combination reaches, formulas that never fire, and the share of dead ends.
    Limit
    The page enumerates up to 16 switches (65,536 combinations). Beyond that it stops and says so. A larger story can still be solved by merging combinations that produce the same events in a section, which can be added when you need it.
